# Resources and Classic Application Assets

The resource fork carries Finder identity, memory and process flags, localized strings, menus, dialogs, controls, versions, and classic icon families. Keep these declarative where practical; create dynamic controls in code only when state or composition requires it.

## Minimum Application Envelope

| Resource | Purpose | Rule |
|---|---|---|
| `cfrg` | CFM fragment metadata | Normally generated by the PowerPC build and packaging path; verify rather than duplicating it by hand. |
| `SIZE` | memory partition and process or event flags | Include `acceptSuspendResumeEvents`, 32-bit compatibility, high-level-event awareness, and honest preferred and minimum memory sizes. Verify foreground and background behavior on target. |
| `vers` | Finder-visible version metadata | Keep semantic and build version synchronized with About UI and diagnostics. |
| `BNDL` and `FREF` | creator and file-type mappings | Use one stable creator code consistently. Map the `APPL` reference and application icon ID. |
| `ICN#` | required 32-by-32 1-bit icon and mask | Supply even when color icon resources are present. Masks are semantic, not copied pixels. |
| `icl4` and `icl8` | 32-by-32 indexed-color icon | Add both depths for a polished Finder presentation. |
| `ics#`, `ics4`, and `ics8` | 16-by-16 small icon family | Supply for list and small-icon Finder views. |

An `icns` resource exists in later interfaces, but it does not replace the classic icon family needed across the 8.6 through 9.2.2 Finder matrix.

## UI Resources

- `MBAR` and `MENU`: menu bar and menus; keep command-key equivalents and enabled or checked states synchronized with the front context.
- `WIND`: static window templates when their structure is stable.
- `DLOG` and `DITL`: alerts, dialogs, and item lists; use resource order as a starting point for keyboard traversal, then verify it.
- `CNTL`: resource-defined controls where a classic proc ID and static bounds fit.
- `STR ` and `STR#`: localized Pascal-string-era UI copy. Do not bury user-facing text in C literals.
- `ALRT`: use standard alert roles and keep variable copy within the measured layout.
- `tab#`, `ldes`, `xmnu`, and color tables: use only when the selected control or API requires them.

## Asset Rules

- Design 1-bit masks first; verify black-and-white readability before color polish.
- Create indexed 4-bit and 8-bit art using system-safe palettes and deliberate dithering.
- Avoid alpha, SVG, PDF, compositing, and runtime scaling assumptions.
- Draw application and module symbols at their actual target pixel sizes. Do not downsample a modern master and call it finished.
- Use Icon Services for semantic system, file, and folder icons; use custom resources for application identity and app-specific modules.
- Check icons at 1-bit, 4-bit, and 8-bit depth with alternate desktop patterns and selected and unselected Finder states.

## Retro68 Build Check

Inspect the repository's `add_application` and Rez integration and generated output. Confirm creator code, resource fork, CFM fragment, preferred and minimum partition, and Finder metadata in the final copied artifact, not only in source files.
