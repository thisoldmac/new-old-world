What this mock is gated by

Exact by construction

  • All geometry from workshop_layout.h: 744×478 content, rail 160, header 38, status 23, nav rows 32, grow box 15
  • Split is fixed, not a draggable splitter — both panes from one compute_rects
  • Memory bar drawn by the module in its own pane — plain QuickDraw, no custom Data Browser column needed
  • Launch date via LongDateString; strings ASCII/MacRoman-safe
  • Quit is an Apple Event request; the row keeps its PSN until the walk proves it gone

Metal-proven at 9.1

  • Data Browser list, header sort, native selection (files page uses it today)
  • Row icons via GetIconRef on type/creator
  • Movable modal confirm that pumps the wire (confirm.c)
  • SetFrontProcess and AE quit are cross-process

Provisional

  • Everything at 8.6 (gate machine: the 3400c, pending screen repair)
  • Data Browser behavior on CarbonLib 1.6 over 8.6 specifically
  • Front & Capture needs extension plane P1 for window bounds
  • The extension group's rung-4 line (per-process windows) is aspiration, drawn ghosted

Not offered

  • Type-select in the list (Data Browser limitation on this runtime)
  • Force quit — no safe kill exists here
  • Seeing another app's windows or controls without the extension (per-process Toolbox wall)
  • A draggable splitter (custom control; not worth it at rung 0)

Fonts are approximated (Charcoal/Geneva fall back to Verdana in a browser) and the desktop weave is set dressing; metrics, control choices, states, and copy are the spec. The detail pane is where the ladder climbs: rung 0 facts and actions today, extension status always honest, and each later rung adds its affordance to the group box rather than redesigning the page.
