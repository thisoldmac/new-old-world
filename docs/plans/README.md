# Plans

**A plan is a snapshot of intent, not a description of the system.**

These are dated roadmap documents written before or during a piece of
work. They are kept because they carry the reasoning and the stop
conditions — *why* a boundary was drawn, and what would have made the
work stop — which is the part that does not survive in a diff.

They are **not** current-state documentation, and they go stale by
design. Where a plan and the code disagree, the code is right and the
plan is a record of what someone expected. Where a plan and
[open-issues.md](../open-issues.md) disagree, the ledger is right.

For what the system actually does now:

- [../status.md](../status.md) — what works and what does not.
- [../contract-coverage.md](../contract-coverage.md) — who serves what.
- [../architecture.md](../architecture.md) — the design and its rules.

Two of these are linked from the README as forward-looking bounds on
host and MCP work; that is the role they still serve. Nothing here
should be read as a commitment to a date.
