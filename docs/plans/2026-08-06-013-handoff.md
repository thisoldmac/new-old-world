## What already works, so you do not rebuild it

- **`qdtrace start mode=probe`** sights a composite blit into the armed
  window and, at the next event-loop pass, finds and hooks the offscreen
  GWorld that owns those pixels. It works: measured `hits`,
  `offscreenPorts 1`, and a `lastMatch` equal to the address a control
  applet independently reported for itself.
- **The offscreen port's ops reach the host already** — they arrive in
  the same drain, keyed by `NowContentRecHeader.port`. What is missing is
  only the *join*, which is the whole of slice A.
- **Three rig applets** in `tools/guest-gworld/src/`:
  `now_gworld.c` (does the mechanism fire at all), `anatomy.c` (structure
  layouts, the QDOffscreen surface, dispatch, and it dumps QuickDraw's
  own code), `loop.c` (**the control** — one GWorld held for the
  process's life, blitted on a cadence, and it reports its own port,
  pixmap, zone bounds and MemTop to a file the rig pulls back).
- **`tools/pef.py`** reads any classic PEF's imports, exports and link
  order. It is how "does the Finder use GWorlds" and the
  CarbonLib-vs-InterfaceLib question were both settled without booting
  anything.

## The measured facts you are building on

Full detail in [docs/toolbox-and-gworld.md](../toolbox-and-gworld.md) and
the corpus findings `gworld-offscreen-ports-are-hookable`,
`memtop-is-not-the-address-space-ceiling`,
`quickdraw-bottlenecks-are-native-ppc-routine-descriptors`.

The four that will shape your code:

1. **`LockPixels` relocates the PixMap RECORD**, out of the application
   zone entirely. Every pointer-shaped key — the blit's source pointer,
   the handle `RecoverHandle` finds from it, `baseAddr` — is a snapshot
   of a block that has moved. Only **shape** survives.
2. **A world is replaced, not updated.** Almost nothing in OS 9 imports
   `UpdateGWorld` (only Graphing Calculator, of nine binaries surveyed).
   Hooks go stale and must be re-established; the host must handle one
   source's ops ending and another's beginning mid-session.
3. **A disposed world's address is reused** by the next `NewGWorld` of
   the same size. Port address alone is not a durable key on either
   side — pair it with the record header's `generation`.
4. **Ops precede their blit.** The host accumulates drawing it cannot
   place until the blit arrives. Bounded retention, dropped when the
   world goes.

## Traps, each one paid for

- **The act plane is broken on `main`.** `ContractMessages.swift` types
  args as `[String: String]`, so every numeric argument crosses as a
  string, the guest's `strtol` reads 0, and **every act replies
  `dispatched` while pressing part 0 at (0,0)**. Fixed on the branch you
  are starting from (`[String: CommandArg]`). `main`'s own
  `open-issues.md` documents it — but only if you read it before
  branching, which is why it is repeated here.
- **Do not re-arm to force a repaint.** Re-arming bumps the generation
  and *unhooks* the offscreen world, so the hooked port is always empty.
  Arm → wait for the chase to hook → *then* stimulate. This single
  ordering mistake hid the Finder's content for an entire session.
- **Do not use `MemTop` as a read guard.** It is ~14.8 MB here while
  application heaps sit ~512 MB above it, so `addr <= MemTop` rejects
  every application pointer and does so **silently**. Bound reads by
  `ApplicationZone()` / `SystemZone()`.
- **QEMU's `memsave` translates through whatever CPU context the machine
  stopped in.** It returned convincing garbage twice in this arc. For
  logical addresses, have a program *on the guest* read them; QMP is for
  pixels and low memory.
- **`ext/` changes are gated.** `tools/ext-bake-gate` refuses a commit
  touching `ext/` or `contract/peek_table.h` unless the stage image
  contains exactly that resident. Defer in writing
  (`TBT_DEFER_EXT_BAKE=1` with a reason) or run
  `scripts/bake-ext-image`. This branch defers deliberately: the probe
  is an experiment and **must not ship armed**.
- **The scene walk goes stale over a long session** — foreign windows
  stop coming back with addresses. Use a fresh VM per phase rather than
  chaining phases on one boot.

## Running the rig

    scripts/build-guests                    # both guests + the applets
    NOW_SPIN_BASE=~/Lab/Assets/os91-qemu/now-mirror-stage.qcow2 \
      NOW_SPIN_RUN=/private/tmp/nowvm-<short> NOW_WIRE_PORT=<free> \
      scripts/spin-up-ppc

`NOW_SPIN_RUN` must be a **short** path (104-byte socket cap; a worktree
path exceeds it and QEMU dies silently). Pick a wire port nothing else
holds — several VMs run on this Mac at once. Stop with
`tools/shutdown-guest.py`, never QMP `quit`, and never by killing what
holds the port (that is QEMU itself).

The driver used for every measurement in this arc is
`tools/gwprobe.py`. Its `--pre` / `--repaint` flags exist because of the
ordering trap above.

## How you will know the slice worked

**One Finder icon-view window rendered host-side with real labels at real
positions, no pixels on the wire.** Icons will be hatched rectangles at
correct positions — that is expected, and deferred item 1 in the plan.

A control run should come first, as it did here: hook `loop.c`'s
persistent GWorld and confirm the join places its `'offscreen row'`
strings correctly, *before* trusting anything the Finder produces. **A
negative from an application means nothing until the control is green** —
that rule cost this arc a night and then saved it.

## What is explicitly not yours

The plan's deferred list, and above all **icon identity** —
`PlotIconSuite` uses `CopyMask` (invisible to `grafProcs`) *unless* the
port is being watched, in which case it renders as two `CopyBits`. The
observer changes the observed, so that experiment has to be designed
around the effect rather than into it. Expect your first composed
interior to show real labels over hatched icon rectangles; that is the
honest result, not a shortfall.

**Discovery is no longer on that list**, and the correction is worth
knowing because it was mine. I deferred it on the assumption that
discovery is a one-off setup cost. This arc's own measurements say
otherwise — a world is *replaced*, not updated, so under continuous
composition discovery runs again on every repaint, and what runs is an
unbounded two-heap scan inside the Finder's draw path. A `NewGWorld`
patch is also the *better* mechanism, not merely the safer one: it hands
over the port at creation, which is the replacement signal slice C would
otherwise infer. It is now **slice D0**, between the join and the
payoff, and it opens with a one-boot experiment rather than a build —
does a trap patch on `NewGWorld` fire for a **CFM** caller at all? If it
does not, the approach does not exist and the fallback is the scan with
a bounded re-discovery budget.
